# Реестр компонентов

Каталог переиспользуемых компонентов на базе shadcn/ui. Живёт в отдельном репозитории
[`senyakoz/ui-kit`](https://github.com/senyakoz/ui-kit) и раздаётся двумя каналами: как git submodule
в приложение Prometey и как shadcn-registry для любого другого проекта.

```bash
npx shadcn@latest add senyakoz/ui-kit/button
```

## Стандарт компонента

- Вариантность только через `class-variance-authority`, без ветвлений по `className` внутри разметки.
- Примитивы оборачиваются в `React.forwardRef`, нативные пропсы пробрасываются дальше.
- У каждого компонента есть `displayName` и экспортируемый тип пропсов.
- Цвета, радиусы, типографика и слои берутся из токенов `registry/default/tokens/tokens.css`.
  Захардкоженных значений быть не должно. Шкалы, список токенов и таблица контраста — на странице
  «Реестр/Шкалы и токены».
- Каждая папка содержит `index.ts`, файл компонента и файл историй. Имя папки в kebab-case.
- Внутренние импорты — только каноническими алиасами: `@/lib/utils` для `cn` и
  `@/registry/default/ui/<name>` для соседних компонентов. Относительные пути между компонентами
  запрещены: shadcn CLI переписывает именно эти алиасы под структуру проекта-потребителя.
- Маршруты, состояние авторизации и бизнес-логика остаются в приложении и приходят пропсами.
  Бренд («Prometey» в `footer` и `navbar-brand`, логотип-гантель) зашит намеренно: это кит Prometey.
  Внешний потребитель меняет его в установленных файлах — код у него свой.

## Состав набора

Таблица строится из `registry.json`, поэтому не может разойтись с манифестом.

<table>
  <thead>
    <tr>
      <th align="left">Item</th>
      <th align="left">Тип</th>
      <th align="left">Категория</th>
      <th align="left">Назначение</th>
      <th align="left">Зависит от</th>
    </tr>
  </thead>
  <tbody>
    {[...registry.items]
      .sort((a, b) => (a.categories?.[0] ?? "").localeCompare(b.categories?.[0] ?? "") || a.name.localeCompare(b.name))
      .map((item) => (
        <tr key={item.name}>
          <td>
            <code>{item.name}</code>
          </td>
          <td>{item.type.replace("registry:", "")}</td>
          <td>{item.categories?.[0] ?? "—"}</td>
          <td>{item.description}</td>
          <td>
            {(item.registryDependencies ?? [])
              .map((dependency) => dependency.split("/").pop())
              .join(", ") || "—"}
          </td>
        </tr>
      ))}
  </tbody>
</table>

Все компоненты, кроме `footer`, используют `cn` из item `utils`. Токены доставляются item `theme`,
поэтому его объявляет каждый компонент — установка одной команды приносит с собой и стили.

## Как добавить компонент

1. Создать папку `registry/default/ui/<name>/` с файлами `<name>.tsx`, `<name>.stories.tsx` и `index.ts`.
2. Собрать компонент по стандарту выше. JSDoc над полями пропсов попадёт в таблицу на странице компонента.
3. Экспортировать компонент и его типы из `registry/default/ui/index.ts`.
4. Добавить запись в `registry/registry.meta.ts`: заголовок, описание, категорию и тип item.
   Файлы, npm-зависимости и registry-зависимости выводятся из импортов автоматически.
5. Пересобрать манифест: `npm run registry:sync`. Манифест правится в том же PR, что и компонент.
6. Прогнать `npm run test`. Проверки манифеста живут в `registry/registry.test.ts`: валидация по
   официальной схеме shadcn, соответствие манифеста исходникам, существование файлов, дубли,
   неверные имена и циклы зависимостей.

## Каналы распространения

| Канал | Кто потребитель | Что получает |
| --- | --- | --- |
| git submodule `ui-kit/` | приложение Prometey | исходники как есть, токены уровней 1-3 импортом `tokens.css` |
| `shadcn add senyakoz/ui-kit/<item>` | любой проект на Tailwind v4 | файлы компонента, `cn` файлом из item `utils`, `tokens.css` файлом и уровень 4 мержем из item `theme` |

## Темы

Светлая и тёмная тема переключаются классом `dark` на корне документа, в Storybook для этого есть
тумблер в панели инструментов, в приложении — компонент `theme-toggle` в навбаре. Страница
«Дизайн-токены» показывает обе темы рядом и проверяет, что каждый токен действительно меняет значение.
Страница «Шкалы и токены» описывает радиусы, spacing, типографику и контраст пар по WCAG AA.
